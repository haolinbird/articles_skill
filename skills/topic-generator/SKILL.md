# Topic Generator - 选题生成

## 运行契约（单独跑 / 被调度器调用都走这一套）

- **输入**：`topics/YYYY-MM-DD.md`（工作区根，topic-collector 的产物；默认取最近一天，用户指定日期时取指定文件）。**文件不存在则提示先跑 topic-collector，不要凭空生成选题**
- **产物**：**不落盘** —— TOP10 选题方案直接输出到对话，由调用方决定落盘位置
  （调度器会在 S1 第 4 步把 TOP3 写入 `articles/YYYYMMDD/topics.md`）
- **幂等**：无副作用，可重复运行
- **前置**：无配置项。受众与赛道口径读 `gzh-write-enhanced/resources/author_voice.md`，改口径改那一份

## 输入数据契约

来自 topic-collector 的每条热点包含固定字段：
`title` / `source` / `url` / `published_at` / `heat` / `summary` / `tags` / `lang`

使用规则：
- `url` 缺失的条目直接跳过
- `published_at` 为 N/A 的条目降权，并在输出中标注「时间待确认」
- `lang` 为「英」的条目需额外评估本土化成本
- `tags` 用于判断与公众号「AI编程应用实战」定位的贴合度

## 生成流程

1. **读取热点文件**：读取工作区根目录下 `topics/YYYY-MM-DD.md`，
   默认取最近一天的文件（用户指定日期时用指定文件）。
   文件不存在则提示先运行 topic-collector
2. **字段校验**：逐条检查上述字段是否齐全
3. **评估筛选**：按选题价值打分
4. **输出TOP10**：完整选题方案

## 受众口径（本节只指路，不定义内容）

**执行筛选前，先 Read `gzh-write-enhanced/resources/author_voice.md`，取其「## 受众」「## 文章赛道」两段作为本技能的口径。**

> ⚠️ 本节**故意不写出受众和赛道的具体内容**。写在任何第二个地方，它就是第二份真相——
> 改人设时只改 `author_voice.md`，这里的副本不会跟着变，选题会静默按旧口径筛。
>
> 唯一定义在 `gzh-write-enhanced/resources/author_voice.md`，改人设改那一份。
> 调度器侧也不保留 `{{AUDIENCE}}` / `{{TOPIC_FOCUS}}` 占位符，同样按该文件的段落取值。

## 筛选标准

### 必须满足
- AI编程相关（Vibe Coding / Claude / AI编程工具 / 影响编程工作流的模型更新）
- 字段完整：有 `url`、有 `summary`
- **受众匹配**：程序员 / 架构师 / CTO 能直接用上；只适合研究者或泛大众的选题降权出局
- **不在排除区**：大模型训练、底层研发、模型评测类一律不选
- 有明确的用户价值（能学到/能用到/能思考）
- 国内用户能理解和关注
- 未命中采集阶段的低质信号

### 加分项
| 维度 | 高分 | 低分 |
|------|------|------|
| 热度 | 讨论量大、增长快 | 冷门、无人问津 |
| 时效 | 24小时内 | 超过3天 |
| 独特性 | 有新角度可挖 | 已被写烂 |
| 可操作 | 能给出具体方法 | 纯概念讨论 |
| 受众匹配 | 程序员 / 架构师当天就能试 | 只有研究者或普通大众感兴趣 |
| 落地场景 | 企业 / 团队真实场景 | 只有 demo 演示 |

## 写作方式分类

根据内容特点选择：

1. **干货教程** - 有具体步骤可复现
2. **产品体验** - 新产品/新功能测评
3. **观点分享** - 趋势分析/行业洞察
4. **新技术突破** - 重大更新/技术解读

## 输出格式

每个选题输出：

```markdown
### 选题 N：[标题]

**事件描述**
一句话说清楚发生了什么

**核心角度**
为什么值得写？独特切入点是什么？

**推荐标题**（3个备选）
1. 标题A
2. 标题B
3. 标题C

**写作方式**：干货教程 / 产品体验 / 观点分享 / 新技术突破

**预估热度**：⭐⭐⭐⭐⭐（1-5星）

**不写的风险**：错过什么？（可选）
```

## 选题公式参考

### 工具测评型
- 用了X天[工具]，我发现[意外收获]
- [工具]的隐藏功能，90%的人不知道

### 方法论型
- 我用[方法]搞定了[问题]的完整流程
- [数字]个让[场景]效率翻倍的技巧

### 热点结合型
- [热点]爆火，但大家忽略了这一点
- 从[热点]看AI编程的未来

### 反共识型
- 别再[常见做法]了
- 为什么我不推荐[热门事物]

### 经验复盘型
- 做了[数字]个[事情]后，我总结的[数字]条教训
- 如果重来一次，我会[改变]

## 质量检查

生成后自检：
- [ ] 标题有冲突感？（数字、对比、反差、疑问）
- [ ] 读者有痛点？
- [ ] 我有独特视角？
- [ ] 有具体案例？
- [ ] 能引发讨论？

5条全中 = 必写 | 3-4条 = 可写 | <3条 = 再想想
