# 公众号文章增强版写作助手 (gzh-write-enhanced)

> **版本**：v1.2（开源版）
> **定位**：把「能看」的 AI 初稿，改写成「像人写的」成稿
> **溯源说明**：四层自检体系的设计思路，参考了业内通行的 AI 文本特征检测方法与中文自媒体写作经验，在此基础上重新组织并扩展为 L1–L4 四层结构。

---

## 运行契约（单独跑 / 被调度器调用都走这一套）

- **输入**：选题方案，取 `articles/YYYYMMDD/topics.md` 的 TOP1（单独跑时也可由用户直接给主题）
- **产物**：`articles/YYYYMMDD/abc.md`（A 版反直觉洞察 / B 版观点分析 / C 版实操教程，三版同文件）
- **幂等**：重跑覆盖同名文件
- **前置**：`resources/author_voice.md` —— **必须先读，且优先级最高**，
  覆盖 `resources/xiaohu_style_dna.md` 与 `resources/xiaohu_narrative_voice.md`（两份第三方人设已标注降级）。
  ⚠️ 若该文件缺失而回退到小虎口吻，**必须在产物头部标注「本次采用第三方小虎口吻，非本人口吻」**，
  否则会静默产出面向中小企业老板的文章，与本人定位冲突。

## 这个 skill 解决什么问题

AI 写出来的文章，最大的问题从来不是「写不出来」，是**一眼就看出是 AI 写的**。

具体表现：

- 满篇「综上所述」「不难发现」「本质上」
- 冒号破折号成灾，标点像机关枪
- 加粗泛滥，整段整段地加粗
- 观点都对，但没有一句是你自己会说的话
- 读完记不住任何一句，更不会转发

这个 skill 用一套**可执行的规则**解决这件事，而不是靠「写得口语化一点」这种正确的废话。

---

## 核心机制：三版并行 + 四层自检

```
素材 / 主题输入
      │
      ├──→ A 版 · 反直觉洞察   （剥洋葱四层结构）
      ├──→ B 版 · 观点分析     （温度感 / 降温段）
      └──→ C 版 · 实操教程     （体验式叙事 / 干货密度）
      │
      ↓
  四层 AI 味自检（L1 硬性 → L2 风格 → L3 内容 → L4 活人感）
      │
      ↓
  A + C 合并成终稿（既值得收藏，又值得转发）
      │
      ↓
  终稿 + 40 个备选标题
```

**为什么是三版？**

三个版本分别解决三种不同的读者需求：A 版负责「转发」（观点冲击），C 版负责「收藏」（干货密度），B 版作为备选风格。三版都写完再合并，终稿才既有洞见又有干货。

## 何时使用这个 skill

触发条件：

- 用户要求写公众号文章，且强调「要有温度」「不像 AI 写的」
- 用户提到「去 AI 味」「活人感」「口语化」
- 用户希望文章通过更严格的质检标准
- 用户已经有一版初稿，想让它读起来更像人写的

## 使用前的配置（重要）

### 1. 作者人设（必须，且优先级最高）

编辑 `resources/author_voice.md`，填好你自己的「我是谁 / 文章赛道 / 受众 / 风格 DNA / 口吻例句」。
**这一步不能跳过**——人设决定了文章的语气和可信度来源。

```
resources/author_voice.md 存在 = 唯一人设基准，覆盖 xiaohu_style_dna.md 的一切冲突设定
resources/author_voice.md 缺失 = 回退到第三方「小虎」人设（见 Step 2.5）
```

没有历史文章也不要紧，先把「我是谁 + 受众 + 风格」三块写实就能开跑，口吻例句后面再补。
填写方法见 `resources/author_voice_TEMPLATE.md`。

### 2. 真人历史语料锚点（wechat_exports/，强烈建议）

`wechat_exports/` 是「去 AI 味」的**治本**机制：把你本人以前写过的文章放进去，写作前自动识别并校准自然语感。
**放进文章后，下次跑流水线自动生效，无需改任何配置。**

- 目录位置：项目根 `wechat_exports/`（与 `articles/`、`topics/` 同级）
- 投放规范：每篇一个 `.md`，放 3–5 篇效果最佳；详见该目录内 `README.md`
- 自动识别：`scripts/voice_sample_index.py` 会扫描该目录、抽取开头/转场/口吻句、按选题相关度推荐
- 空目录时打印 `NO_SAMPLES` 并优雅降级，流水线退回 `author_voice.md` 单基准（行为与之前一致，不报错）
- **与 `author_voice.md` 的关系**：`author_voice.md` 是硬性身份基准（身份/受众/禁用），始终最高优先级；
  `wechat_exports/` 只做软性语感校准，绝不覆盖硬约束（见 `author_voice.md` 对应小节）

## 写作流程

### 入口 A：素材直写

用户提供主题 / 素材，直接生成文章。

#### Step 1：收集输入

必须拿到：

- **文章主题**：要写什么
- **核心素材 / 案例**：有什么具体案例、数据、工具
- **目标读者**：谁会看
- **字数要求**：默认 2000 字左右

#### Step 2：真人语料校准（wechat_exports/ 存在时自动执行，否则跳过）

**这一步是「去 AI 味」的治本机制，必须按以下顺序走：**

0. **先固化图片（防外链失效）**：动笔前先把历史文章里的外链图片下载到本地 `wechat_exports/assets/<文章名>/` 并改写引用，避免日后图片链接过期/防盗链导致本地看图时图裂。脚本幂等（已下载则跳过），失败不中断：
   ```bash
   # 用 Glob 找到 **/localize_article_images.py 取绝对路径后运行
   python3 <localize_article_images.py 绝对路径>
   ```
1. 动笔前再跑扫描脚本，自动识别语料（脚本会自动定位项目根，cwd 无关）：
   ```bash
   # 用 Glob 找到 **/voice_sample_index.py 取绝对路径后运行；--topic 给当前选题用于相关度排序
   python3 <voice_sample_index.py 绝对路径> --topic "<当前选题>" --top 3
   ```
   - 输出 `NO_SAMPLES` → 目录为空，**跳过本步**，退回 `author_voice.md` 单基准（与旧行为一致，不报错）。
   - 输出 `FOUND N 篇` + `RECOMMENDED` 路径列表 → 进入第 2 步。
2. 用 `Read` 工具**全文读取** `RECOMMENDED` 列出的 1–3 篇（按选题相关度排序），重点学三件事：
   - **开头怎么起**：第一句是否直接抛经历 / 反差，而非宏大铺垫；
   - **转场怎么用**：真人实际用了哪些口语词、密度多高（用来校准，而不是硬凑）；
   - **第一人称怎么讲**：怎么用「我 / 我们」带出体感，而非旁观者总结。
3. 带着这些真人口语纹理去写 A/B/C 三版。`author_voice.md` 的硬约束（禁用词 / 标点 / 禁编）全程生效，
   语料只做风格对齐、不覆盖身份。

> 没有历史文章也完全可用，本步会自动跳过。脚本为纯标准库实现，任意 `python3` 可跑。

#### Step 2.5：加载作者人设（强制，先定「谁在写」）

**⚠️ 写作前必须先确定口吻归属，不读 = 返工。按以下顺序，命中即停：**

1. **`resources/author_voice.md`**（本人人设，**最高优先级**）—— 存在则以此为准，
   并**覆盖**下面第 2 项里的一切冲突设定
2. `resources/xiaohu_style_dna.md` + `resources/xiaohu_narrative_voice.md`
   （第三方「小虎」人设，1975 生 / 浙大计算机本硕 / 青玥AI 主理人 / **受众 = 中小企业家老板群体**）
   ——**仅当第 1 项不存在时**才加载

> **为什么必须写死顺序**：小虎那份自称「唯一风格基准、覆盖一切旧受众」，但它面向中小企业老板，
> 与技术向作者（程序员 / 架构师 / CTO）的受众正好相反。两者并存时若不声明优先级，
> 模型会静默采用更详细的那份，产出跑偏的文章。
> 若你确实要写小虎口吻，删掉或改名 `resources/author_voice.md` 即可。

三版结构可以各有分工，但**叙事口吻必须统一为 author_voice.md 定义的本人**，
交稿前逐条过口吻自检（走小虎分支时，改用 narrative_voice 里的口吻自检七条）。

#### Step 3：生成 A / B / C 三版

分别加载三个模板，各写一版。三份模板的 Role 头部已按 `resources/author_voice.md` 填写；
若你替换了该文件，**必须同步核对三份模板开头的 Role 段**，否则头部仍会写旧人设。

| 版本 | 模板文件 | 核心结构 |
|------|----------|----------|
| **A 版** | `resources/prompt_A_反直觉洞察.md` | 剥洋葱：现象拆解 → 认知翻转 → 底层逻辑 → 商业实验 |
| **B 版** | `resources/prompt_B_观点分析.md` | 观点推进 + 降温段，重温度感 |
| **C 版** | `resources/prompt_C_实操教程.md` | 体验式叙事：先亮结果，再拆步骤 |

#### Step 4：三版通用的六条硬规则

以下规则在 A / B / C 三个版本中统一生效，不分版本：

1. **结果前置**：先给结果 / 案例 / 数据，再讲方法。读者第一眼看到的是「这人做成了」，不是「这人要讲道理」。
2. **金句锚点**：每篇必须产出 1 个可截图传播的金句。标准是截一张图发朋友圈就能传播，不需要上下文。
3. **诚实坦白**：每篇必须承认 1–2 个不足或局限，用口语化的方式。不是正式的「局限性说明」，是「说实话，这东西也有坑」。
4. **口语化转场词**：自然穿插，宁少勿假。全篇 2–4 处即可，不硬凑；若机械堆叠超过 6 处（每两三段就甩一个）反而判为 AI 味，打回。真人闲聊不会轮流上「好家伙」「坦白讲」。
5. **往期文章导流**：结尾放 2–3 篇本系列往期文章链接，形成内部流量循环。
6. **软转化结尾**：不硬推不卖课，姿态是「我先把价值给你了，你觉得有用再来」。

#### Step 5：四层 AI 味自检（强制）

调用 `resources/checklist_ai味.md` 逐层扫描：

```
L1 硬性规则 → L2 风格一致性 → L3 内容质量 → L4 活人感终审
```

**四层全部通过才算达标，任何一层不通过都要返工。**

- L1 / L2 的问题可以自动修复（替换禁用词、改标点）
- L3 / L4 的问题必须人工改写（补案例、重写段落）

#### Step 6：加粗控制

- 加粗总量不超过全文字数的 **5%**
- 每篇加粗不超过 **5–8 处**，宁缺毋滥
- 判断标准：**这句话删掉，文章就缺一块的，才值得加粗**
- 只加粗名词术语、关键数据；观点句、情绪表达、口语化金句不加粗

#### Step 7：生成 40 个备选标题

按 `resources/40titles_template.md` 的 8 类风格各 5 个，放在正文最开头。

#### Step 8：A + C 合并成终稿（强制）

三版完成后，必须将 **A 版** 和 **C 版** 合并为一篇终稿。

合并要求：

- 逻辑通顺，看起来像一篇文章，不是拼接
- 段落之间要有自然过渡
- 保留 A 版的洞见深度和观点冲击力
- 保留 C 版的实操步骤和干货密度
- 让读者既愿意收藏（干货），又愿意转发（洞见）
- **合并后需再次通过四层 AI 味自检**

合并后的终稿作为最终输出。

## 口语化技巧速查

详细技巧见 `resources/style_tips.md`，核心要点：

### 口语化转场词

- ✅ 「说真的」「坦白讲」「其实吧」「说实话」「好家伙」「我跟你说」「你别笑」
- ❌ 「接下来让我们讨论……」

### 情绪表达

- ✅ 用具体动作 / 反应描述情绪（体感记忆）——琢磨了一下、试试看、打个问号、一下就通了
- ❌ 用抽象形容词描述情绪（知识描述）——「我感到非常震撼」「我非常惊讶」
- ⚠️ 「愣住」偶尔可用，但别每篇都用

### 禁用词

- ❌ 「说白了」「意味着什么」「本质上」
- ❌ 「综上所述」「首先……其次……最后」

### 禁用标点

- ❌ 冒号 `：` → 用逗号替代
- ❌ 破折号 `——` → 用逗号替代
- ❌ 双引号 `""` → 用「」替代

## 注意事项

1. **人设要一致** —— 先填好 `{{作者人设}}`，全篇保持同一个人的口吻
2. **价值优先** —— 每篇必须有认知差、方法论、商业洞察中的至少两项
3. **四层自检是强制的** —— L1 / L2 / L3 / L4 必须全部通过才能输出
4. **口语化 ≠ 随便说，也 ≠ 硬凑** —— 口语化是手段，活人感才是目标；转场词宁少勿假，机械堆叠 6 处以上直接判 AI 味
5. **先跑通再改** —— 第一次用建议先跑 A 版，感受一下四层自检的威力，再上三版流程
