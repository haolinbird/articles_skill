# 公众号文章转多平台

## 运行契约（单独跑 / 被调度器调用都走这一套）

- **输入**：终稿 Markdown + 已生成的配图。调度器链路下喂 `articles/` 下的原生稿（非 `final_gzh.md` 内联样式版），
  **跳过「WebFetch 原文 + 下载图片」步骤**（配图已由上游生成）。独立使用时也接受文章 URL 或直接粘贴正文。
- **产物**：由 `config/platforms.json` 各平台的 `output_files` 决定 —— **以该文件的实时值为准，不要照抄本文档的任何示例文件名**
- **幂等**：重跑覆盖对应平台文件
- **前置**：**执行前必须先读 `config/platforms.json`**（决定启用哪些平台、产出什么文件）；
  若还要同步草稿箱，另需 `config/pipeline.env` 里的 `WECHATSYNC_TOKEN`（仅 S6 需要）

将用户提供的微信公众号文章，按照各平台的内容风格和格式特点，转换为适配的发布内容。**核心原则①：只做风格转换和格式适配，严禁杜撰、添加或超出原文内容范围的任何信息。** **核心原则②：内容详实度必须与原文一致，只换风格、不删减内容。** 原文中的具体案例/示例、数据、比喻、金句、细节铺垫、结尾行动建议必须全部保留，任何平台都不得为追求"简短"而删减原文信息（具体到各平台时仅可调整表达方式，如小红书用短句+emoji呈现，但要点一个不能少）。

## 〇、启用平台（执行前必读）

> **本节是指针，不是数据源。** 平台启用状态、输出文件名、同步参数全部由
> `config/platforms.json`（项目根）决定，本节刻意不复制其中任何值，避免产生第二份真相。

**执行前必须先 Read 该文件，不得凭推测或上次的印象决定跑哪些平台：**

```
/Users/haolin/WorkBuddy/AI编程公众号SKILL/config/platforms.json
```

判断规则（全部读自 `platforms[].enabled`）：

| 字段值 | 含义 | 本次执行动作 |
|---|---|---|
| `enabled: true` | 启用 | 产出该平台 `output_files` 列出的文件；`wechatsync.supported` 为 true 的，在 S6 同步 |
| `enabled: false` | 暂停 | 全部跳过：不产 md、不生成小红书图、不跑 `scripts/md_to_plain.py`、不在 S6 同步 |

**暂停平台的处置**：下面的平台规则全部**保留不删**（恢复时直接用），但 `enabled: false` 的平台
即使已登录也**不同步**，产物也不生成。

**启用 / 停用某个平台**：改 `config/platforms.json` 里该平台的 `enabled` 即可，**本节与调度器 S5/S6 都不用动**。

> 历史教训：2026-10-09 之前，启用一个平台需改 **4 处**（本节表格、调度器 S6 稳定性矩阵、
> S6 警告块、调度器产物清单），而文档声称「只改一处」是错的。收敛后为 **1 处**。
> 本文档若再出现平台清单或 ✅/❌，一律视为应删除的冗余副本。

## 一、完整工作流程

### 1. 接收文章
- **优先推荐方式**：用户提供公众号文章 URL 链接
- 通过 WebFetch 获取文章全文内容，**同时提取文章中的图片 URL**
- 如果用户只提供文本，也支持直接粘贴内容（但会缺少原文图片）

### 2. 下载原文图片
- 从 WebFetch 返回的内容中，提取所有图片的 URL（`<img src="...">` 或 Markdown `![](...)` 格式）
- 使用 Python 脚本或 PowerShell 将图片下载到输出目录，命名为 `YYYYMMDD_图片_01.jpg`、`YYYYMMDD_图片_02.png` 等（保持原始格式）
- 如果图片下载失败（防盗链等），跳过该图片，但记录日志提示用户
- **⚠️ 强制规则：下载了多少张图片，就必须在文章中全部引用，一张都不能漏！**
  - 图片在原文中出现在什么位置，转换为各平台文章时就放在对应位置
  - 每张图片用 `![](YYYYMMDD_图片_XX.xxx)` 引用
  - 不要把图片堆在文末，要按原文顺序分散插入到对应段落之间
  - 如果某张图片在原文中对应某段文字，转换后那段的 Markdown 里必须有这张图片
- 下载的图片将用于：
  - 各平台文章中的配图引用（知乎、头条、百家号等）
  - 小红书图文笔记的素材
  - Wechatsync 同步时的封面图

### 3. 确认输出目录
- 询问用户希望输出到哪个目录（如用户未指定，默认输出到当前工作目录）
- 输出目录下会产生一组文件，命名格式为 `YYYYMMDD_平台名`（日期取当天日期）

### 4. 逐平台转换
- 按照下方各平台转换规则，逐一生成对应格式的内容
- 每完成一个平台，就输出到对应文件中
- **各平台的内容中，如果原文有图片，必须在 Markdown 中引用本地下载的图片路径（相对路径）**

### 5. 图片生成（仅限需要图片的平台）
- 小红书：必须生成图片（图文格式）。优先使用原文下载的图片，不足时调用 GenerateImage 补充
- 其他平台：在 Markdown 中引用原文下载的图片作为配图
- 调用 GenerateImage 工具生成图片时，图片保存到输出目录下

### 5. GPT Image2 API 配置

图片生成使用 OpenAI 兼容的 API 接口，配置如下：

```
API Key: {{GPT_IMAGE_API_KEY}}
Base URL: {{GPT_IMAGE_BASE_URL}}
```

**调用方式：**
- 使用 OpenAI SDK 或兼容的 HTTP 请求调用图片生成接口
- 请求格式（以 OpenAI Python SDK 为例）：
  ```python
  from openai import OpenAI
  client = OpenAI(
      api_key="{{GPT_IMAGE_API_KEY}}",
      base_url="{{GPT_IMAGE_BASE_URL}}"
  )
  response = client.images.generate(
      model="gpt-image-2",
      prompt="图片描述（基于原文内容提炼）",
      size="1024x1024",
      n=1
  )
  ```
- 下载返回的图片 URL 保存到本地输出目录

**图片生成要求：**
- 图片 prompt 内容只能来自原文提炼，不得添加原文没有的信息
- 小红书图片：3:4 竖版风格，清新明亮，适合社交媒体
- 其他平台图片：根据平台风格调整

## 二、各平台特点与转换规则

### 平台1：知乎（Zhihu）

**平台特点：**
- 深度阅读平台，用户期望有深度、有逻辑、有干货的长文内容
- 支持 Markdown 排版，重视段落间距、空行、标题层级
- 文章风格偏理性、分析性强，注重"为什么"和"怎么做"
- 开头需要有吸引力的引子（hook），常用"谢邀"体或提问式开头
- 喜欢用数据、案例、引用支撑观点，强调逻辑严密
- 常用加粗、引用块、列表等排版元素突出重点
- 结尾常有总结或互动引导（如"你怎么看？欢迎评论区讨论"）

**转换规则：**
1. 标题改为知乎风格的提问式或观点式标题（如"如何评价XXX？""XXX的底层逻辑是什么？"）
2. 开头增加引子段落，提炼文章核心问题或观点
3. 正文结构化为：引入 → 分点论述 → 深度分析 → 总结
4. 使用 Markdown 格式：合理使用 `##`、`###` 标题层级，`**加粗**` 突出重点，`>` 引用块引用关键句子
5. 段落间保持适当空行，每段不超过4-5行
6. 原文中的论述展开为更有逻辑性的分析，但**不添加原文没有的事实、数据、案例**
7. 结尾加入互动引导语
8. 输出格式：`.md` 文件

### 平台2：小红书（Xiaohongshu / RED）

**平台特点：**
- 以视觉为主的社交平台，图文笔记为核心形式
- 用户偏爱色彩明亮、活泼、有视觉冲击力的图片
- 文字风格轻松、口语化、有亲和力，多用 Emoji 和网络用语
- 标题需要吸睛、简洁、有悬念或利益点
- 正文短小精悍，通常不超过1000字，大量使用分段和列表
- 每篇笔记必须有高质量封面图
- 文字与图片相互呼应，图片上可加文字标注
- 常用标签（hashtag）增加曝光

**转换规则：**
1. 标题改为小红书风格：简洁吸睛，带 Emoji，突出关键词和利益点（如"🔥 3分钟搞懂XXX，太香了！"）
2. 正文改写为口语化短文案：
   - 用短句，每句不超过20字
   - 大量使用 Emoji 表情作为视觉分隔符
   - 使用数字列表（1️⃣2️⃣3️⃣）或 bullet point 呈现要点
   - 人称改为"我""你""姐妹们""宝子们"等口语化表达
3. 提取原文全部核心要点，用短句+emoji 呈现（小红书是短句风格，不是删减理由——原文的案例、数据、金句、三个底层事实、对照表、结尾行动必须全部保留，一个都不能少），**不添加原文没有的内容**
4. 文末添加相关标签（hashtag），如 `#XXX #干货分享 #自我提升`
5. 生成配图（调用 GenerateImage）：
   - **封面图**：尺寸 3:4 竖版，包含标题文字和吸引眼球的视觉元素，风格清新明亮
   - **内容图**（1-3张）：将核心要点制作成图文卡片，文字简洁，背景统一风格
6. 同时输出 `.md` 文案文件（纯文字部分）和图片文件
7. 图片保存路径：`{输出目录}/YYYYMMDD_小红书_封面.png`、`{输出目录}/YYYYMMDD_小红书_图1.png` 等

### 平台3：今日头条（Toutiao）

**平台特点：**
- 算法推荐驱动，标题决定打开率，前100字决定读完率
- 用户群体广泛，偏好通俗易懂、接地气的表达
- 文章风格偏资讯化、故事化，语言通俗直白
- 标题需要醒目、有冲击力、制造悬念或引发好奇
- 正文开头要快速抓住读者注意力（hook）
- 结构清晰，善用小标题分段，每段不宜过长
- 内容偏向实用主义和情绪共鸣
- 篇幅通常在800-2000字之间（这是平台内容常态描述，**不是转换时的删减上限**；正文分段、用短句即可，原文内容不得删减，超出篇幅直接保持原文长度）

**转换规则：**
1. 标题改为头条风格：醒目、有冲击力，使用数字、疑问、对比等手法（如"XXX背后，藏着3个惊人真相"）
2. 开头用1-2句话制造悬念或共鸣，快速抛出核心看点
3. 正文语言口语化、通俗化：
   - 专业术语改为大白话表达
   - 多用短句，少用长难句
   - 适当加入"你可能会问""说白了就是"等口语化过渡
4. 用小标题（`##`）将内容分成3-5个模块，每个模块有明确主题
5. 关键观点或金句用 `**加粗**` 突出
6. 结尾做简短总结，并抛出互动问题
7. 输出格式：`.md` 文件

### 平台4：百家号（Baijiahao）

**平台特点：**
- 百度旗下自媒体平台，内容会被百度搜索收录，需考虑SEO
- 偏好原创、有价值、结构规范的内容
- 标题不宜过长，最好不超过14个字，需包含关键词
- 文章排版规范：字号15-16px、行距1.5-1.75倍、对齐统一
- 段落首行不缩进，段间距适中
- 需要封面图（尺寸600×400像素），风格统一
- 正文颜色不超过3种，重点句子加粗
- 文章需要有明确的摘要（约100-150字）
- 内容质量要求较高，拒绝低质和营销内容

**转换规则：**
1. 标题改为百家号风格：简洁规范（不超过20字），包含核心关键词，适合搜索引擎收录
2. 开头写一段100-150字的摘要（description），概括全文核心内容
3. 正文结构规范：
   - 一篇文章有明确的"引言-正文-结语"三段式结构
   - 使用 `##` 小标题分隔各板块
   - 每段控制在3-5行
4. 语言风格：正式但不僵硬，专业但不晦涩，保持客观中立的基调
5. SEO优化：
   - 在首段和末段自然融入核心关键词
   - 小标题包含长尾关键词
6. 重点句子用 `**加粗**` 标注
7. 结尾附上文章摘要回顾
8. 输出格式：`.md` 文件

### 平台5：稀土掘金（Juejin）

**平台特点：**
- 面向程序员和互联网技术从业者的技术社区
- 内容以技术文章、开发经验、行业洞察为主
- 推崇高信息密度、实战价值强的干货内容
- 支持 Markdown 排版，代码块是标配
- 文章风格：技术化、结构化、逻辑清晰
- 喜欢"总-分-总"结构，常见模式：背景 → 问题 → 方案 → 实现 → 总结
- 标题通常直接点明技术点和价值（如"XXX 最佳实践""手把手教你 XXX"）
- 社区氛围偏理性和技术导向，拒绝营销软文

**转换规则：**
1. 标题改为掘金风格：直接点明技术/知识主题和价值（如"深入理解 XXX：从原理到实践"）
2. 将原文内容重新组织为技术文章结构：
   - 导语：说明背景和读者能学到什么
   - 核心内容：用结构化方式呈现（对比表格、步骤列表、原理分析等）
   - 总结：提炼关键要点
3. 如果原文涉及技术概念，用代码块或技术术语准确表达，**但不得添加原文未提及的技术细节**
4. 使用 Markdown 排版：合理使用表格、代码块、列表、引用等
5. 语言风格偏技术化但不生硬，突出"干货"属性
6. 如果原文是非技术类内容，则保留核心信息，以"经验分享"或"行业洞察"的形式呈现
7. 输出格式：`.md` 文件

#### 稀土掘金发布字段（S5b 排版规范，2026-10-07 新增）

掘金用**原生 Markdown 渲染**，排版方式与公众号不同：

- ⚠️ **禁止喂公众号的内联样式版**（`_final_gzh.md`）。内联 HTML 在掘金会被部分剥离，残留样式很丑，代码块和表格尤其容易坏。
- 排版产物是 `YYYYMMDD_pN_稀土掘金_发布版.md` = **YAML frontmatter（发布字段）+ 原生 Markdown 正文**。
- frontmatter 供人工在掘金编辑器里填，Wechatsync 不会读它；正文保持标准 Markdown，图片继续用 `![]()` 本地相对路径（Wechatsync 会上传替换为 CDN）。

frontmatter 字段（**照抄结构，值按当篇实际内容填，禁止编造数字**）：

```yaml
---
title: 文章标题
description: 80-120 字摘要，掘金列表页展示
tags: [标签1, 标签2, 标签3]        # 3-5 个，掘金标签最多 5 个
categories: [后端, 架构]            # 掘金分类，选最贴的 1-2 个
cover: 封面图相对路径                # 建议用该篇的第 1 张配图
---
```

正文排版要求：

- 一级标题只留文章主标题一个，其余用 `##` / `###`
- 表格、代码块原样保留（掘金渲染良好）
- 图片分散插在对应段落之间，不堆文末
- 结尾保留「素材来源与出处」表（掘金社区重视引用出处）

### 平台6：知识星球（ZhiShiXingQiu / AI群星会）

**平台定位：**
- AI群星会 是 AI 从业者、创业者和超级个体的付费社群，成员多为实操派，对"虚的"容忍度极低
- 内容调性：**真诚、有料、不装**。星友花钱进来要的是真实经验和可落地的干货，不是公众号式的"科普文"
- 默认称呼社群成员为"星友们"，营造"内部交流、独家分享"的氛围

**AI群星会风格核心要素：**

1. **标题**：直接点明主题，不需要标题党，但要让人一看就知道"这对我有用"。格式参考：
   - 观点式：`WorkBuddy连上可画，AI做图终于能改字了`
   - 结果式：`实测了一下午，这份活稿让我省了80%的改图时间`
   - 禁止：公众号式标题（"重磅！XXX发布""震惊！XXX来了"）

2. **开头（决定星友是否读完）**：必须在 3 句话内建立"这是内部人写的"的感觉。
   - 用"星友们"开头，像深夜在群里跟朋友聊天
   - 分享一个具体场景或个人实测经历，让读者觉得"这是真干过的人写的"
   - 示例："星友们，我下午刚实测了一个东西，忍不住连夜写出来。"
   - 禁止：科普式铺垫（"随着AI技术的发展..."）、公众号式渲染（"今天要给大家介绍一个重磅功能..."）

3. **正文结构**：干货 + 实操 + 踩坑 + 金句，每部分用 `---` 分隔线隔开。
   - **干货**：把核心观点用最直白的话讲清楚，不要绕。用对比（"图 vs 活稿"）让概念一目了然
   - **实操**：有步骤就写步骤，有模板就给模板，让星友看完能直接抄
   - **踩坑**：必须诚实写出局限性、踩过的坑、不适合的场景。星友最反感"只说好的不说坏的"
   - **金句**：每个板块至少有一句能让人想截图的话（加粗突出）

4. **语气要求**：
   - 极度口语化，像在微信群发长消息，不是写文章

### 平台8：短视频口播文案

**平台特点：**
- 面向抖音、快手、视频号等短视频平台的口播类内容
- 核心是"黄金3秒"：开头3秒内必须抓住观众注意力，否则划走
- 语言极度口语化，像在跟观众面对面聊天
- 单条视频文案控制在200-400字之间（对应约60-120秒视频），保持内容的深度和完整性，不要为了缩短时长而牺牲内容质量
- 结构模式：钩子开头 → 冲突/反差 → 抛出问题 → 展开观点 → 金句收尾 → 固定结尾语"你的固定结尾语（按你自己账号写，如「关注XX，普通人也能XX」）"
- 多用反问、设问、感叹等句式增强感染力
- 纯口播文案，不添加任何表情符号、语气标注（如停顿、强调、语速变化）或表演提示
- **爆款文案的本质**：不是"记录经历"，而是"制造情绪落差"。让观众在30秒内经历一次"被抓住 → 被戳中 → 得到答案 → 想转发"的情绪完成度。

**爆款文案方法论（必须遵守）：**

1. **黄金3秒钩子公式**：第一句话必须给观众一个"不划走的理由"。可选类型（完整 12 类钩子见 `xiaohu-copy-library` 的 `01-钩子库`）：
   - 反常识结论（"你以为XX？其实根本不是。"）
   - 惊人数字/结果（"我没花一分钱，做成了XX。"）
   - 直接戳痛点（"你是不是也一直在加班？"）
   - 悬念预告（"这个办法，90%的人第一步就做错了。"）
   - 身份共鸣（"做老板的，这条视频一定要看完。"）
   - ⚠️ 禁止：用"今天分享""最近做了""大家好"这类平淡开场，等于把观众送走。
   - ⚠️ 禁止：把口播写成"我的经历自述、流水账"，爆款口播的主角是"观众"，不是"我"。开头必须抛出一个让观众觉得"这跟我有关"的观点或争议，而不是介绍自己。

2. **冲突/反差设计**：爆款靠"意料之外"抓人。找出原文里最反常识、最反直觉的点，把它放大成"冲突"：
   - 身份反差（"我一个写代码的，居然被出版社颁了证书"）
   - 认知反差（"你以为学AI的是年轻人？其实是老板。"）
   - 结果反差（"没花钱、没人脉，却办成了"）
   - 必须在开头就抛出这个反差，用它吊住观众。

3. **戳痛观众**：把原文的观点落到"观众自己的处境"上：
   - 用"你""你不""你是不是"把观众拉进内容
   - 让观众产生"这说的就是我"的代入感
   - 痛点要具体（加班、获客难、内容做不出来），不要空泛

4. **情绪曲线**：整条文案要有起伏，不是平的：
   - 开头：制造好奇或戳痛（情绪被勾起）
   - 中间：给干货/给反转（情绪被满足）
   - 结尾：升维成普适道理 + 一句可以截图的金句（情绪被推向高潮）
   - 情绪曲线 = 好奇 → 认同 → 震撼 → 想保存/转发

5. **金句/转发钩子**：结尾前必须有一句"让观众想截图、收藏、转发"的话：
   - 句式：短、有对比、有哲理、可套用（如"一个人加AI，顶得过去一整个部门"）
   - 这句话要能脱离上下文独立成立，成为观众转发时的文案
   - 金句是传播的种子，没有金句的口播没有转发力

6. **叙事类内容如何爆款化**（处理"讲经历/讲故事"类原文时）：
   - 不要平铺直叙"我做了什么"，要提炼"这件事让我恍然大悟的点"
   - 把"经历"包装成"发现/教训/方法"，让观众觉得看完有收获
   - 用"你知道吗/你会发现/说白了"制造认知升级感
   - 结尾一定要落到"对观众有什么用"，而不是回到"我"

## 四、核心约束（必须严格遵守）

6. **格式正确**：严格使用 Markdown 格式，确保标题层级、列表、加粗等格式正确。

- 各平台登录状态会过期，**每次同步前先 `wechatsync auth` 复核**，不要照抄历史记录。

### 知识星球图片上传方法（已验证可用）

**核心流程（三步）：**
1. **获取上传 token**：`call_zsxq_api` 调 `POST /v2/uploads`，body 为 `{"req_data": {"type": "image", "size": <文件字节数>, "name": "", "hash": ""}}` → 返回 `resp_data.upload_token`
2. **上传图片到七牛云**：用本地脚本 POST multipart 到 `https://upload-z1.qiniup.com/`，表单含 `file`（图片字节）和 `token`（上一步拿到的 upload_token）两个字段 → 返回 `resp_data.image_id`
   - ⚠️ token 字符串不能有 BOM/多余空白，读文件时用 `utf-8-sig`
   - 同一 token 在有效期内（约1小时）可复用多张图
   - 参考脚本：`{{WORK_DIR}}\zsxq_image_upload.py`
3. **发布时带上图片**：`create_topic` 的 `args` 里加 `"image_ids": [id1, id2, ...]`（最多9张）

注意：`zsxq.js` CLI（cookie 方式）因 cookie 被官方封禁不可用（401），走 MCP 连接器是当前唯一可行的图片上传通道。

### 直连 api.zsxq.com 通道（备用，2026-09-07 实测结论）

- 用户提供的 32 位 hex key `＜32位hex凭据已脱敏＞` 直连官方 API 返回 401（`Bearer <key>` 与 `Cookie: zsxq_access_token=<key>` 两种方式、带不带浏览器 UA 均试过）→ 该 key 不是有效的网页版 access token，可能是连接器侧凭据。
- 若日后拿到有效的网页版 token（浏览器登录 wx.zsxq.com → F12 → Application → Cookies → 复制完整的 `zsxq_access_token` 值，注意别截断），可直接 HTTP 发布：
  1. `POST https://api.zsxq.com/v2/topics`，头 `Authorization: Bearer <token>`，body `{"req_data":{"type":"talk","text":"<纯文本>","title":"<标题>","group_id":<group_id数字>}}`
  2. 传图同上三步（`POST /v2/uploads` → 七牛 multipart → `image_ids` 字段随 topics 一起发）。
- token 与 group_id 配置存档：`{{WORK_DIR}}\.workbuddy\config\zsxq.json`。

### 已知坑：会话中途连接连接器，MCP 工具不可见

- WorkBuddy 的 deferred 工具索引在会话启动时生成。**会话中途才连接的连接器（如 zsxq），当前会话里 ToolSearch 搜不到它的工具，直接调用报 not found** → 需要新开会话/重启会话后工具才可用。
- 流水线自动化（05:30 无人值守）是每次新开会话，天然不受影响；只有当天交互会话里临时连的连接器会遇到。
- 降级规则不变：工具调不了 → 纯文本版列人工待办，不阻塞流水线。

### 图片生成注意事项

- GenerateImage 生成的小红书配图实际保存为 `.jpg` 格式（不是 `.png`），文件名中写 `.png` 但实际扩展名是 `.jpg`
- 图片 prompt 中不要要求生成中文文字（GenerateImage 对中文文字支持不好），改为纯视觉表达
- 小红书封面图尺寸用 `portrait_4_3`（3:4竖版），内容图同理
- 原文下载的图片保持原始格式（`.jpg`、`.gif` 等），不要强制转 `.png`
